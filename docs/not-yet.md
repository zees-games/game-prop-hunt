# Not yet

What this game does not do yet, each with where the detail is.

- **Workshop props do not join the disguise pool.** `provides.json` accepts subscribed maps only (`map_kind` `prophunt`, kinds `["map"]`), because a disguise is a measured hull, not a look. A pack prop would need, in solo: a `props/catalogue.json` row made at load (a size measured from the pack's `scene` or its `DotPropDef`, the `kit` and recolour, pieces, `breaks`, a title), a `PhProps.instance` that can load a mounted scene, and the stand-ins' `may_disguise` taking it. Online it also needs the id on the wire (a DISGUISE event carries only a catalogue id the other end must hold) and both ends measuring to the same hull, which `headless_net` asserts. None of it is cheap, so the entry kind `prop` is not in `accepts`. [design](design.md#decision-1-a-disguise-is-a-hull-not-a-look)
- **A Workshop map is a prop-hunt map document, not a scene.** The entry is `{"kind": "map", "map_kind": "prophunt", "scene": "<path>.json"}`: `scene` names the same JSON document `maps/` holds (see `maps/README.md`), because this game builds a map from boxes and catalogue props and has no scene-based map. A pack map can use only the props the game's own catalogue has. [delivery](delivery.md)
- **A pack map claiming an id of the game's own can show on the ballot.** The catalogue keeps the game's map (the built-in practice house always wins), but dot-vote's `follow_content` only de-duplicates against the ids in the source's own list, which leaves the practice house out once there are other maps. The row reads "Name [Pack]"; choosing it is harmless because `PhGame` plays a next map only if the catalogue lists it. Fixing it needs a reserved-ids list on `DotVoteListSource`.
